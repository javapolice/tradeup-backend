\# TradeUp 기술 선택 원칙



\## 1. 기본 원칙



TradeUp에서는 기술 자체를 사용해보는 것을 목표로 하지 않는다.



먼저 문제를 정의하고, 해당 문제를 해결하기 위해 필요한 기술을 선택한다.



새로운 기술을 도입할 때는 다음 질문에 답할 수 있어야 한다.



1\. 현재 어떤 문제가 발생했는가?

2\. 기존 방식으로 해결하기 어려운 이유는 무엇인가?

3\. 왜 이 기술을 선택했는가?

4\. 다른 대안은 무엇이 있었는가?

5\. 기술 도입 후 어떤 점이 개선되었는가?

6\. 새롭게 발생한 복잡성이나 단점은 무엇인가?



\## 2. 초기 기술 방향



초기 애플리케이션은 가능한 단순한 구조로 시작한다.



기본 방향은 다음과 같다.



\* Java 25 (LTS)

\* Spring Boot 4.1.0

\* Spring Data JPA

\* PostgreSQL 18

\* Gradle (Kotlin DSL)

\* 단일 애플리케이션 구조



Redis, 메시지 브로커, 검색 엔진, 컨테이너 오케스트레이션 등의 기술은 초기부터 도입하지 않는다.



실제 문제를 재현한 뒤 필요성이 확인되었을 때 단계적으로 도입한다.



\## 3. 기술 도입 기록



중요한 기술적 의사결정은 문서로 남긴다.



각 결정에는 다음 내용을 포함한다.



\* Problem

\* Alternatives

\* Decision

\* Reason

\* Result

\* Trade-off



이를 통해 최종 결과뿐 아니라 기술적인 판단 과정도 포트폴리오에서 보여주는 것을 목표로 한다.
